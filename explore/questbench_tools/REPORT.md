# QuestBench GSM-Q as native tool calls: Dolos-1.5B vs Qwen2.5-1.5B-Instruct

Generated by `analyze.py` from `results.json`. Greedy decoding, bf16, H100, batch 1, max_new_tokens 64.

## Data and design

- Source: belindazli/QuestBench, config GSM-Q, split test; first 100 rows fetched; 50 items selected as the shortest valid rows by 'Rewritten Problem' length (max 371 chars).
- Items: 50 rows, but only 45 distinct problem texts (the dataset has several GT variants per problem). Per-item results are therefore not independent; treat n as <=50 items over fewer problems.
- Tool order: GT tool first in 24/50 items (seeded shuffle).
- Generations: 300 of 300 expected.

Conditions: **T1** tool_first (tools passed, GT vs distractor tool call); **T2** mc_text (no tools, A/B letter of the question to ask); **T3** post_answer (tools passed; history contains GT tool call and an invented result `12`; final user turn asks for `DONE`).

## Caveats

- n=50 items over 45 distinct problems; one model-facing wording per condition; greedy decoding only. CIs are Wilson 95% and do not account for item clustering.
- T1 and T2 are not identical prompts: T2 adds a 'which question' lead-in and lists options as A/B text with no tools.
- T3's tool result (`12`) is invented and is not the true answer; it only probes whether the model stops calling tools after receiving a value.
- The distractor is the other possible question in the dataset, not a guaranteed-irrelevant one; 'other' calls (names outside the two tools) are reported, not hidden.
- Failures are reported as observed. No threshold or prompt tuning was done after seeing outputs.
